## 真机验收矩阵

1. 未认证用户：只能浏览公开内容，不能发帖、评论、互动、查看联系方式或提交装修需求。
2. 待审核业主：提交认证后保持审核中，不重复进入认证页，不获得发布权限。
3. 认证业主：可发布、评论、互动、参与问题投票；仅主动授权后可让装修需求被商家分配。
4. 商家：仅在系统管理员授权的板块发帖，所有商家帖子进入审核；只能查看自身获分配的线索。
5. 板块管理员：仅审核、下架、置顶其负责板块的内容；不能封禁用户、处理全局隐私请求或授权商家。
6. 系统管理员：审核认证和商家，配置商家板块，维护交付资料、广告位、线索、隐私申请和运营台账。

## UI 验收

- 在 375px 模拟器和真机检查发布 CTA、评论输入区、认证页返回、分类页返回和底部 TabBar。
- 检查长标题、长按钮文案、空列表、加载态与重复点击，不应发生文字裁切或控件重叠。
- 检查常用操作的触控区域不小于约 44px，底部安全区不遮挡内容。
- 对已授权装修需求检查“撤回授权”确认框和结果反馈，确保按钮不挤压需求摘要，撤回后状态文案正确更新。
- 以系统管理员新增一条商家合作记录，分别验证合同金额、实收金额和退款金额边界；修改记录后在 `audit_logs` 中检查新增/更新操作。
- 上传公开帖子图片和商家案例图，确认云端图片安全检测通过后才能入库；模拟检测失败时，应提示用户更换图片且不创建记录。
- 以系统管理员选择已授权商家创建广告位，确认未选择商家时服务端拒绝保存、首页轮播展示“广告 · 商家名称”，并检查广告创建和下架审计记录。
- 在认证页不勾选隐私说明提交，确认页面阻止；直接调用 `verifyInvite` 时传入 `privacyAccepted: false`，确认云端也拒绝；成功提交后核对 `users.privacyAcceptedAt`。
- 使用非管理员账号直接调用数据库 SDK 读写任一集合，确认被规则拒绝；随后通过对应云函数验证正常浏览和提交仍可使用。
- 用两名不同账号分别完成认证审核、评论、帖子审核、商家审核与线索分配；仅对应当事人的“消息通知”应出现消息，消息中不得包含房号、联系方式和评论正文。
